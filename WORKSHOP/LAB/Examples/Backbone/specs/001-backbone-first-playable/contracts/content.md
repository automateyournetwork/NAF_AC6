# Contract: content files

Everything a reviewer may want to check without reading code lives in `src/content/` as data (C6). `src/content/load.ts` validates each file when the game starts and when the tests run. A file that fails validation stops the game with a text message; it is never silently patched.

## `tuning.json`

Play-balance numbers. Not rules, except where noted.

| Key | Unit | Start value |
| --- | --- | --- |
| `stepsPerSec` | steps | 20 |
| `tiers` | packets per second per direction | [4, 8, 16] |
| `queueLen` | packets per direction | 8 |
| `utilWindowSec` | seconds | 2 |
| `busyPct`, `congestedPct` | percent utilization | 50, 90 |
| `meterSize`, `meterDrainDelaySec`, `meterDrainIntervalSec` | drops, seconds, seconds | 100, 3, 1 |
| `rewardEverySec`, `rewardFiberKm` | seconds, km | 60, 3000 |
| `graceSec` | seconds | 20 |
| `startSites`, `siteEverySec`, `maxSites` | sites, seconds, sites | 3, 40, 12 |
| `startFiberKm`, `startUpgrades` | km, upgrades | 8000, 1 |
| `baseRateMilli`, `rateGrowthMilliPerMin` | thousandths of a packet per second, per unit of site weight | 500, 200 |
| `firstCutSec`, `cutEverySec`, `cutLenSec` | seconds; the last two are [low, high] ranges | 150, [50, 80], [12, 25] |
| `kmPerSec` | km of map per second | 1200 |

All values are whole numbers. `meterSize`, `meterDrainDelaySec` and `meterDrainIntervalSec` are also written in the spec (FR-010); a test fails if the two disagree.

## `region-na.json`

```text
{ "id": "na", "name": "North America", "lon0": …, "lat0": …,
  "sites": [ { "code": "DEN", "name": "Denver", "lon": …, "lat": …, "weight": 1 }, … ] }
```

Rules: `code` is three upper-case letters and unique; `lon` and `lat` are in range; `weight` is 1, 2 or 3; there are at least `maxSites` sites. Adding a region is a new file of this shape plus its checks, with no change to the simulation.

## `coast-na.json`

`{ "rings": [ [lon, lat, lon, lat, …], … ] }`. Decoration only. Generated by `tools/build-map.mjs` from Natural Earth data and never read by the simulation.

## `palette.json`

`{ "<role>": "#rrggbb", … }`. Every color the game uses, by role: background, panel, grid, coast, link, pulse, site, text, muted text, focus, congestion (amber), failure (magenta), and so on. Rules: six-digit hex only; no color in the green band (hue 75° to 165°) or the red band (below 25° or above 340°) once it is strongly colored (FR-032). No other file under `src/` or `index.html` may contain a color literal.

## `text.json`

All explanatory text the player reads, so it can be reviewed against the spec in one place (C1):

- `briefing`: the one-card briefing, word for word from the spec.
- `faithful`: F1–F8, and `simplified`: S1–S11, each `{ "id", "text" }`, in plain language. A test checks that every ID is present exactly once.
- `reasons`: one sentence for each reason code in `contracts/simulation.md`.
- `help`: the short control hints.

## Trial region

`tests/fixtures/region-trial.json` is a second region of the same shape, used by a test that runs the unchanged simulation on it (C6 evidence).
